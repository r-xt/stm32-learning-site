# 维护说明

## 目录职责

| 目录 | 内容 |
|---|---|
| `docs/getting-started/` | 环境与最小开发闭环 |
| `docs/courses/` | 单一主题课程 |
| `docs/tracks/` | 能力路线和阶段出口 |
| `docs/boards/` | 板卡、工具和文档阅读 |
| `docs/projects/` | 综合项目指南 |
| `docs/resources/` | 经核验的原始资料入口 |
| `docs/assets/` | 本站样式和本地交互脚本 |
| `scripts/` | 环境、构建和检查脚本 |

## 内容状态

建议在新课程 front matter 中增加状态，并仅把可学习内容加入主导航：

- `stable`：已在目标硬件验证，步骤和验收完整；
- `draft`：结构可见但尚未完成验证；
- `archived`：为旧芯片或旧工具保留，不再作为推荐路线。

当前 MVP 导航中的六篇课程均按可执行教程编写；由于具体板卡可能不同，使用者仍须按板卡文档替换引脚和外设实例。

## 更新流程

1. 从[课程模板](lesson-template.md)创建页面。
2. 在 `mkdocs.yml` 的 `nav` 中加入导航。
3. 更新相关路线、项目和前后课程链接。
4. 在真实目标板上按页面从头执行，并记录板卡与工具版本。
5. 运行 `构建离线版.cmd`；只有严格构建和检查都通过才提交。
6. 检查浅色、深色和窄屏布局，再发布 `dist` 中的离线包。

## 版权与引用

- 本站课程正文应以原创解释和实验记录为主。
- 官方 PDF 只做摘要、文档编号、版本、章节/页码和链接，不复制整份到仓库。
- 外部示例代码须遵循原仓库 LICENSE；大仓库不直接复制进课程目录。
- 对安全、勘误、产品状态和工具版本等易变化信息标注核验日期。

## 学习进度数据

进度键名为 `stm32-learning-progress-v1`，只保存在浏览器本地。导出格式包含 `version`、`exportedAt` 和 `lessons`。修改结构时必须保留旧格式迁移逻辑，避免用户升级站点后丢失记录。
